# Cashback Merge

Cashback Merge — консольный симулятор игры в духе 2048. Одинаковые плитки с кэшбэком объединяются: `1 + 1 = 2`, `2 + 2 = 4` и так далее до максимальной награды. После успешного хода на поле появляется новая плитка.

Проект позволяет настраивать правила игры и параметры кампании, запускать серию партий и оценивать, какая доля игроков получает максимальную награду.

## Структура проекта

```text
src/
├── CashBackMerge.Game/       # игровое поле, ходы, объединение и игровые конфиги
├── CashBackMerge.Simulator/  # кампании, стратегии, загрузка конфигов и Markdown-отчёты
└── CashBackMerge.Tests/      # тесты
```

Игровые JSON-конфиги находятся в `src/CashBackMerge.Simulator/JsonConfigurations`. При сборке они копируются рядом с приложением. Отчёты сохраняются в `MarkdownReports` рядом с запущенным приложением.

## Сборка и тесты

Из корня решения выполните:

```bash
dotnet build CashBackMerge.sln
dotnet test CashBackMerge.sln
```

## Запуск симуляции

```bash
dotnet run --project src/CashBackMerge.Simulator -- --game defaultGame.json --campaign defaultCampaign.json --seed {номер сида} --output report.md
```

Аргументы `--game` и `--campaign` обязательны. Их значения — имена JSON-файлов в папке `JsonConfigurations`.

| Аргумент | Назначение |
|---|---|
| `--game` | Файл с настройками игрового поля и появления плиток |
| `--campaign` | Файл с числом игроков, стратегией и допустимой долей максимальной награды |
| `--seed` | Начальное значение для генерации игровых сессий; если не указано, выбирается случайное |
| `--output` | Имя Markdown-файла; по умолчанию `report.md` |

Например, с приведённой выше командой отчёт будет создан в `MarkdownReports/report.md` рядом с приложением. При обычном запуске через `dotnet run` это, как правило, `src/CashBackMerge.Simulator/bin/Debug/net10.0/MarkdownReports/report.md`. Расположение не зависит от текущей папки терминала.

## Конфигурация

### Игровой конфиг

Файл `JsonConfigurations/defaultGame.json`:

```json
{
  "mapSize": 4,
  "movesLimit": 35,
  "maxRewardCashback": 32,
  "initialState": [1, 1],
  "spawnRules": [
    { "value": 1, "probability": 0.85 },
    { "value": 2, "probability": 0.1 },
    { "value": 4, "probability": 0.05 }
  ]
}
```

- `mapSize` — размер квадратного поля.
- `movesLimit` — число успешных ходов до завершения партии. Ход, который не меняет поле, лимит не расходует.
- `maxRewardCashback` — максимальная плитка и награда.
- `initialState` — значения плиток, случайно размещаемых в начале партии.
- `spawnRules` — значения новых плиток и их вероятности. Вероятности должны быть положительными и в сумме равняться `1`.

### Конфиг кампании

Файл `JsonConfigurations/defaultCampaign.json`:

```json
{
  "playersCount": 100000,
  "strategyName": "random",
  "maxRewardAllowedRate": 0.1
}
```

- `playersCount` — количество симулируемых партий.
- `strategyName` — стратегия ходов: `random` или `circle`.
- `maxRewardAllowedRate` — предельная доля игроков, получающих максимальную награду, от `0` до `1`. Например, `0.1` означает `10%`.

Конфиги проверяются до начала симуляции. В частности, проверяются лимит ходов, допустимые значения плиток и правил появления, а также сумма вероятностей.

## Игровые правила

- Поддерживаются направления `Up`, `Down`, `Left` и `Right`.
- Одинаковые соседние плитки сливаются по правилам 2048; новая плитка, полученная при слиянии, не сливается повторно в тот же ход.
- Ход без изменений не расходует лимит и не создаёт плитку.
- После каждого изменившего поле хода появляется одна новая плитка согласно `spawnRules`.
- Получение максимальной плитки само по себе не завершает партию.
- Счёт увеличивается на значение плиток, полученных при слиянии.

## Отчёт

Markdown-отчёт содержит параметры кампании и игры, средний и максимальный счёт, среднюю награду, распределение игроков по максимальной плитке и фактическую долю игроков с максимальной наградой. В конце указывается статус кампании: `ОК`, если фактическая доля не превышает лимит, иначе `Failed`.

Пример фрагмента отчёта:

```text
## Результаты кампании

- Средний счёт: 127,1556
- Максимальный счёт: 202
- Средний размер награды: 18,36
- Распределение наград:
    8: 324 (3,24%)
    16: 8039 (80,39%)
    32: 1637 (16,37%)
- Доля игроков с максимальной наградой: 16,37%

## Статус: Failed
```

## Ограничения

- Seed задаёт воспроизводимое состояние генератора игровых сессий и появления плиток. Стратегия `random` использует собственный генератор случайных ходов, поэтому для повторяемого сценария используйте `circle`.
