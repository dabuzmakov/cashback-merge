# Cashback Merge

Cashback Merge — консольный симулятор игры в духе 2048. Одинаковые плитки с кэшбэком объединяются: `1 + 1 = 2`, `2 + 2 = 4` и так далее до максимальной награды. После успешного хода на поле появляется новая плитка.

Проект позволяет настраивать правила игры и параметры кампании, запускать серию партий и оценивать, какая доля игроков получает максимальную награду.

## Структура проекта

```text
src/
├── CashBackMerge.Game/
│   ├── MoveEngine/          # поле, плитки, направления и результаты ходов
│   ├── Sessions/            # состояние и жизненный цикл партии
│   ├── Configuration/       # игровые настройки и их валидация
│   └── Randomness/          # случайный выбор значения плитки по весам
├── CashBackMerge.Simulator/
│   ├── Campaigns/           # запуск кампании и итоговая статистика
│   ├── CLI/                 # разбор аргументов запуска
│   ├── Configuration/       # загрузка JSON и проверка настроек кампании
│   ├── Configs/             # JSON-конфиги
│   ├── Reporting/           # формирование и сохранение отчётов
│   └── Strategies/          # стратегии выбора ходов и их фабрика
└── CashBackMerge.Tests/
    └── Mandatory/           # тесты конфигурации, seed, движка и отчётов
```

JSON-конфиги находятся в `src/CashBackMerge.Simulator/Configs`. При сборке и публикации папка `Configs` копируется рядом с приложением. Отчёты сохраняются в `MarkdownReports` рядом с запущенным приложением.

## Запуск симуляции

```bash
dotnet run --project src/CashBackMerge.Simulator -- --game defaultGame.json --campaign defaultCampaign.json --seed 67 --output report.md
```

Аргументы `--game` и `--campaign` обязательны. Их значения — имена JSON-файлов в папке `Configs`. В примере используется seed `67`; его можно заменить другим целым числом.

| Аргумент | Назначение |
|---|---|
| `--game` | Файл с настройками игрового поля и появления плиток |
| `--campaign` | Файл с числом игроков, стратегией и допустимой долей максимальной награды |
| `--seed` | Seed кампании, определяющий случайность партий и стратегии `random`; если не указан, выбирается случайное значение |
| `--output` | Имя Markdown-файла; по умолчанию `report.md` |

Например, с приведённой выше командой отчёт будет создан в `MarkdownReports/report.md` рядом с приложением. При обычном запуске через `dotnet run` это, как правило, `src/CashBackMerge.Simulator/bin/Debug/net10.0/MarkdownReports/report.md`. Расположение не зависит от текущей папки терминала.

## Конфигурация

### Игровой конфиг

Файл `Configs/defaultGame.json`:

```json
{
  "mapSize": 4,
  "movesLimit": 20,
  "maxRewardCashback": 32,
  "initialState": [1, 1],
  "spawnRules": [
    { "value": 1, "probability": 0.6 },
    { "value": 2, "probability": 0.2 },
    { "value": 4, "probability": 0.15 },
    { "value": 8, "probability": 0.05 }
  ]
}
```

- `mapSize` — размер квадратного поля.
- `movesLimit` — число успешных ходов до завершения партии. Ход, который не меняет поле, лимит не расходует.
- `maxRewardCashback` — максимальная плитка и награда.
- `initialState` — значения плиток, случайно размещаемых в начале партии.
- `spawnRules` — значения новых плиток и их вероятности. Вероятности должны быть положительными и в сумме равняться `1`.

### Конфиг кампании

Файл `Configs/defaultCampaign.json`:

```json
{
  "playersCount": 10000,
  "strategyName": "circle",
  "maxRewardAllowedRate": 0.1
}
```

- `playersCount` — количество симулируемых партий.
- `strategyName` — стратегия ходов: `random`, `circle` или `greedy-score`. Имя задаётся в нижнем регистре.
- `maxRewardAllowedRate` — предельная доля игроков, получающих максимальную награду, от `0` до `1`. Например, `0.1` означает `10%`.

Конфиги проверяются до начала симуляции. В частности, проверяются лимит ходов, допустимые значения плиток и правил появления, а также сумма вероятностей.

## Стратегии

| Имя | Как выбирается ход |
|---|---|
| `random` | Случайное направление из четырёх; генератор получает seed партии |
| `circle` | Повторяющаяся последовательность `Down → Left → Up → Right`, начиная заново в каждой партии |
| `greedy-score` | Перебор четырёх направлений на копиях поля и выбор хода с наибольшим приростом счёта |

`greedy-score` пропускает ходы без изменений. При равенстве очков выбирается первое подходящее направление в порядке `Right`, `Down`, `Left`, `Up`. Оценка выполняется до появления новой случайной плитки, без просмотра следующих ходов.

`random` и `circle` могут выбирать направления, которые не меняют поле. Такие попытки не расходуют лимит ходов. Жадная стратегия максимизирует очки за один ход, но не гарантирует наибольшую итоговую награду.

## Игровые правила

- Поддерживаются направления `Up`, `Down`, `Left` и `Right`.
- Одинаковые соседние плитки сливаются по правилам 2048; новая плитка, полученная при слиянии, не сливается повторно в тот же ход.
- Ход без изменений не расходует лимит и не создаёт плитку.
- После каждого изменившего поле хода появляется одна новая плитка согласно `spawnRules`.
- Получение максимальной плитки само по себе не завершает партию.
- Плитки со значением `maxRewardCashback` больше не сливаются.
- Счёт увеличивается на значение плиток, полученных при слиянии.
- Партия завершается при исчерпании лимита успешных ходов или отсутствии доступных ходов.
- Награда партии равна значению максимальной плитки на поле.

## Отчёт

Markdown-отчёт содержит параметры кампании и игры, средний и максимальный счёт, среднюю награду, распределение игроков по максимальной плитке и фактическую долю игроков с максимальной наградой. В конце указывается статус кампании: `ОК`, если фактическая доля не превышает лимит, иначе `Failed`.

Иллюстративный фрагмент отчёта (числа не являются результатом запуска с конфигами выше):

```text
## Результаты кампании

- Средний счёт: 127,1556
- Максимальный счёт: 202
- Средний размер награды: 18,36
- Распределение наград:
    8: 324 (3,24%)
    16: 8039 (80,39%)
    32: 1637 (16,37%)
- Доля игроков с максимальной наградой: 16,37%

## Статус: Failed
```

## Воспроизводимость

Seed кампании используется для получения seed каждой партии. Этот seed передаётся игровой сессии и фабрике стратегий. Для каждой партии создаётся отдельная стратегия; `random` использует собственный генератор, инициализированный seed партии.

При одинаковых конфигах и seed кампании результаты воспроизводимы для всех трёх стратегий, включая `random`
