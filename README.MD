# Игра Cashback Merge

## Идея

Мини-игра в духе 2048 на поле 4x4. На поле появляются плитки с кэшбэком, две одинаковые объединяются в следующую:

1% + 1% = 2%    2% + 2% = 4%    ...    16% + 16% = 32%


У игрока ограниченное число ходов, цель — собрать максимальный кэшбэк. Но у проекта есть второй, «продуктовый» слой: по итоговой плитке начисляется награда, и максимальную награду должна получать ограниченная доля игроков — например, не больше 20% в batch-симуляции.

## Зачем это в реальной работе

Промо-игры, розыгрыши кэшбэка и бонусные механики стоят компании реальных денег. Прежде чем запускать такую кампанию на миллионы пользователей, нужно ответить на вопрос: «А сколько мы заплатим?» Для этого механику балансируют — настраивают вероятности, лимиты ходов — и проверяют симуляциями, какая доля игроков доберётся до дорогой награды.

В этом проекте вы пройдёте весь цикл: игровой движок → конфигурируемая кампания → симуляция на тысячах «игроков» → отчёт со статусом OK / FAILED. По сути, это упрощённая версия инструмента, которым продакт и аналитик проверяют экономику промо-акции до запуска.

## С чем придется столкнуться
Конфигурируемое поведение — параметры кампании живут в конфиге, а не в коде
Точная арифметика — проценты и вероятности без неточного float
Инварианты и явные ошибки — обработка невалидного конфига до старта
Симуляции и статистика — эмпирическая проверка бизнес-ограничения
Воспроизводимость — одинаковый конфиг + seed + стратегия → одинаковый отчёт

## План: три MR
### MR1 — Модель, конфиг, начальное состояние

Поле 4x4, плитки с уровнями кэшбэка, состояние игры, конфиг кампании с загрузкой из файла и валидацией, создание начального состояния по seed, текстовый вывод поля.

Пример spawn-правил:

{
  "spawnRules": [
    { "cashback": "1", "probability": "0.85" },
    { "cashback": "2", "probability": "0.15" }
  ]
}


Инварианты: поле 4x4, координаты в границах, одна плитка на клетку, movesLimit > 0, spawn-правила не пусты, вероятности корректны и в сумме дают 1.

Важно: проценты и вероятности храним без неточного float — строки, дроби или целые в базисных пунктах.

### MR2 — Движок ходов
applyMove(state, move) -> moveResult


Ходы UP / DOWN / LEFT / RIGHT, сдвиг и объединение по правилам 2048:

[1, 1, empty, empty] -> LEFT -> [2, empty, empty, empty]
[1, 1, 1, empty]     -> LEFT -> [2, 1, empty, empty]
[1, 1, 1, 1]         -> LEFT -> [2, 2, empty, empty]
[2, 2, 4, 4]         -> LEFT -> [4, 8, empty, empty]


Ключевые правила:

одна плитка не объединяется дважды за ход: [1, 1, 2, empty] -> [2, 2, ...], а не [4, ...];
invalid move не тратит ход и не создаёт новую плитку;
после валидного хода появляется ровно одна новая плитка;
игра не заканчивается при достижении 32% — игрок доигрывает до лимита ходов;
расчёт score; случайность spawn'а отделена от merge-логики.

### MR3 — Награды, симуляция, отчёт
weighted random для появления плиток;
таблица наград, итоговая награда по максимальной плитке;
batch-симуляция с минимум одной стратегией игрока: random;
проверка бизнес-ограничения:
{ "maxRewardCashback": "32", "maxRewardAllowedRate": "0.20" }

actualMaxRewardRate <= maxRewardAllowedRate -> OK, иначе FAILED


Пример запуска:

simulate --config campaign.json --players 10000 --strategy random --seed 42 --output report.md


Отчёт (текст, JSON или Markdown): игроки, лимит ходов, seed, стратегия, распределение максимальных плиток и наград, средний и максимальный score, доля игроков с максимальной наградой, статус OK / FAILED.

Честная оговорка: это не математическая гарантия. Ограничение проверяется эмпирически — для конкретного конфига, seed, числа игроков и стратегии. Так и работают реальные проверки баланса.

## Что должны покрывать тесты
Область	Что проверяем
Конфиг	валидный принимается; сумма вероятностей ≠ 1 или movesLimit <= 0 — отклоняется
Seed	одинаковый конфиг + seed → одинаковое начальное поле и одинаковый отчёт симуляции
Merge	все четыре примера строк из MR2
Двойной merge	[1, 1, 2, empty] -> [2, 2, empty, empty]
Invalid move	не меняет поле, не тратит ход, не создаёт плитку
Spawn	после валидного хода — ровно одна новая плитка
Завершение	после N валидных ходов игра завершена
Награда	максимальная плитка 16% → награда соответствующего tier
Симуляция	отчёт содержит распределение наград, долю max reward и статус
